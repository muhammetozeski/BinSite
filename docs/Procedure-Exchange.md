# Procedure Exchange

Procedure Exchange is one independent C# Blazor product at `/procedure-exchange/`, catalog ID 99. It combines useful local execution with a public exchange of versioned methods. It does not count an editorial method, view or fork as another site. Its catalog entry has `adEligible: false`; public discovery and private editing share the same runtime without third-party advertising scripts.

## Local work and original content

The initial authoring view needs neither a key nor an account. Twelve explicitly labelled original editorial methods cover catalog cleanup, version-linked revision delivery, short prototype playtests, event information, release notes, publication checks, agreed meeting actions, community sessions, readable handoffs, sheet reconciliation, product-photo batches and sharing-safe project copies. Every method contains at least five substantive actions, observable done checks, three required inputs and a concrete expected artifact. They are packaged source content, not fabricated user publications or engagement.

A local editable method has canonical public fields only: title, summary, category, tags, input descriptions, expected artifact and stable-ID steps. Each step separates its action from its observable done check and estimated minutes. Incomplete drafts can be saved privately; running, exporting reusable instructions and publishing require a complete canonical method. Methods allow at most 40 steps, 20 inputs, six tags and 48 KiB of compact UTF-8 public text.

Starting a run clones a complete method snapshot and hashes that snapshot. Editing or reordering the author's draft does not rewrite any earlier run. Runs started directly from a real public response pin its exact ID and revision. A run started from the editable draft is labelled local, retaining its source separately; edited work is not presented as an exact published revision. Content hashes detect accidental drift, not signed execution or identity.

Private run fields contain actual input values, per-step declared checks, notes and evidence, artifact text and a result note. Finishing is an explicit completed/partial/blocked declaration. Completed requires every declared check, an artifact record and a result note; it is not independently verified performance. A finished local record must be explicitly reopened before editing. No local action automatically submits a public outcome. Up to twenty runs fit one local project, subject to its four-megabyte JSON limit. Work is in tab memory until the visitor downloads JSON or explicitly saves a private account copy.

## Portable output and replacement boundaries

The private project download includes incomplete draft content, source metadata, immutable run snapshots and actual execution records. Strict JSON restoration rejects unknown fields, invalid identities, duplicate step IDs, inconsistent run references and snapshot drift. The entire candidate is validated before replacing the open project. Starting a blank project, opening a starter, restoring a file or loading a private copy requires a specific replacement confirmation. A restored file always clears any publication overwrite target; a local file is never accepted as proof that its holder owns a server record.

A reusable JSON package includes only the complete canonical method and source attribution. Its private inputs, run notes, evidence and artifacts are excluded. Method HTML is a standalone, script-free, encoded document. Run HTML is pinned to the chosen snapshot and omits private execution text by default; a separate explicit checkbox includes it. The artifact text download contains the actual recorded artifact text rather than generated claims of completion. Review downloaded reports before sharing. Local files remain editable by their holder and are not authenticated approval records.

`procedure-exchange.js` handles only selected local text files, Blob downloads, explicit replacement confirmation and clipboard access with a visible-link fallback. It performs no network fetch, writes no browser storage and interprets no authored HTML. Domain rules and output encoding remain C# source.

## Public versions and real outcomes

The browser adapter uses the existing [public procedure service](Procedure-Service.md) at `/api/commerce/procedures`. Its search lists only actual public records; `mine=true` uses the real account session. The initial public corpus was empty after service fixtures were removed. Editorial methods remain in a separately labelled authoring section and are never substituted for real public search records or statistics.

Public reads can select an exact immutable revision. Share links contain only a public ID and revision. A fork retains that source pin and a full local source snapshot, allowing comparison of inputs, output criteria, stable-ID actions, done checks, timing and ordering. Server reads remain authoritative about ownership and visibility. Explicit owner editing records the expected publication revision; publishing a stale update preserves the local draft and surfaces the server refusal without retrying the mutation. Imported/private drafts can be reconnected to a selected real owned record through an explicit action, without replacing the draft.

Publishing requires an actual account, a self-supplied publisher alias and explicit permission for copying, attributed export and forking. An alias is not represented as a verified real name or expert credential. The client constructs a new whitelisted canonical method document; it never posts the local workspace, input values, runs, evidence or artifact text into public publication. A public method itself must still be checked by its author for confidential information.

The outcome form sends only the selected immutable revision, an explicitly selected result and a bounded public note. It is separate from the local run controls and does not prefill private records. Counts are actual account-submitted self-reports for that revision; an account's replacement report is an update, not another participant. No success rate or verified-user claim is inferred. Owners can withdraw their public method after confirmation. A report records a review request and does not claim automatic removal. Already downloaded independent files are not rewritten by withdrawal.

## Optional private copies

`ProcedureExchangeVaultClient` uses the existing owner-only `/api/commerce/projects` route with `kind: procedure`. It does not use the collaborative workspaces table. An explicit private label has a separate 100-character limit; the full 120-character method title stays inside the saved body. Each JSON body is limited to 64 KiB on either plan. Free and active-member accounts share the existing three/one-hundred private-item allowance with the other products. Membership may add capacity; local authoring, runs and file exports remain usable without it.

The vault provides an owner copy with last-save replacement, not invitations, immutable history or optimistic revision checking. Replacing a selected copy requires confirmation. Loading a copy validates the file and clears publication overwrite targets. The real account page is `/uyelik/`; no synthetic login, subscription or success state is created by this UI.

## Source and executed checks

The product owns `Models/ProcedureExchangeModels.cs`, `Services/ProcedureExchangeRules.cs`, `Services/ProcedureExchangeContent.cs`, `Services/ProcedureExchangeExports.cs`, `Services/ProcedureExchangeClient.cs`, `Pages/ProcedureExchange.razor`, its `.razor.cs` and isolated `.razor.css`, and `wwwroot/procedure-exchange.js`. It reuses the existing `SocialApi` transport for same-origin account requests and metadata-only logging. No shared production layer was changed to support a test.

An isolated .NET 10 harness linked those actual domain, content, export and client source files. Forty-one assertions passed: all twelve rich methods validate; run snapshots detach; exact and derived sources stay distinct; private restore preserves work while clearing overwrite targets; public/package projections omit private sentinels; unknown fields, duplicate step identities, oversized public documents and snapshot drift are rejected; incomplete drafts remain portable; completion/reopen controls behave as declared; HTML encodes authored markup and defaults to private-text omission; actual artifact output is preserved; source comparison detects check changes and reordering; public payloads whitelist eight canonical fields; outcome payloads contain only three explicit fields; private title/label boundaries are separate and invalid labels send no request. The harness and fake transport are disposable test consumers outside the source tree.

A coordinated full Release build of the shared Blazor project passed with zero warnings and zero errors. The initial build exposed one repeated pattern-variable name inside this product's error display; it was corrected before the successful build. Browser-bridge adapter checks exercise selected text-file reads, size refusal, exact Blob payload/download naming, URL release, confirmation and clipboard fallback. They do not claim an actual browser download or rendered live product check. The root agent separately owns deployment and browser acceptance. The public service's SQL and live production checks are documented in Procedure-Service.md; those results are not presented as browser UI verification.

An independent component audit found that changing the private-report checkbox while a download awaited its browser acknowledgement could make the completion message disagree with the already generated report. The export now captures that choice once before awaiting and uses it for both HTML creation and the completion message; the checkbox is disabled while an action is busy. The exact paused-download fixture was changed into a regression against an isolated Razor compilation of the updated component, using the unchanged production domain/export assembly. It passed both directions: included private text still produces an inclusion message after the live flag is forced off, and redacted text still produces an omission message after the live flag is forced on. No shared source layer or shared build was required for that regression.
