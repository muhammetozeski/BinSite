# Project instructions

Read README.md first. Work only on assigned product folders and catalog batch files when collaborating. Keep apps independently usable at their own paths, with no parent shell restricting their interface or architecture. Do not overwrite another agent's work or use the portfolio directory as a product template. Do not store secrets. Only record verified publication and usage. Product explanations are Turkish; source identifiers and project documentation are English. Commit each coherent change separately without authorship trailers. Use docs/ for architecture and deployment evidence.

Read [the documentation guide](docs/Documentation-Guide.md) and [knowledge index](docs/İçindekiler.md); follow relevant links. Preserve project-specific verified lessons as part of implementation, distinguish code/documentation evidence from execution evidence, and update obsolete material. Keep plans and progress in dated handover records rather than knowledge articles. Follow [the Walkthrough guide](Walkthrough/Walkthrough-Guide.md): select recent context and relevant lessons by filename, and append a dated record when results affect continuation. Never invent publication, revenue, users, or completed scope.
