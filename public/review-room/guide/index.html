Start with one real delivery

Give the project a useful title and a short delivery brief. Add the files you want to review. A logical asset can hold several versions of one image or one video; it is not a folder of unrelated files. Keep a banner and a separate feature card as separate assets.

If you want to inspect the workflow first, open the three editorial example packages. Each package includes two sample images and example notes so you can try the controls.

What makes one version different from another?

Files are recognized by their contents. Renaming a file does not create a new version. Add a changed file as a new version and give it a clear label.

Keep your original files. A saved review project contains identities, comments and decisions; it does not embed the media or upload it to an image host. When someone opens your JSON on another device, they reconnect matching originals. A filename alone is not enough to impersonate an existing revision.

Write a comment that points to a decision

For an image, select the exact version and click the relevant place. The marker is stored as coordinates relative to that image. The center action gives a keyboard-accessible way to start a note. For video, pause at the relevant frame and choose Use current video time; the recorded timestamp comes from the video player.

Vague feedbackActionable feedback
“The date is wrong.”“At marker 2 on Version 2, replace the date with the supplied final date before delivery.”
“This part is too fast.”“At the recorded video time, keep the title visible long enough to read it before the next cut.”
“Looks good.”“The currently selected version is ready for review; the remaining open notes are optional refinements.”

Choose a category and distinguish an ordinary note from a blocking change. A blocking change prevents recording approval while it remains open. A note can remain useful without claiming that the whole delivery must stop.

Follow the recorded version, not the newest filename

When an edited file arrives, add it to the same logical asset as a new version. The old comments remain attached to their original bytes. Compare the versions' notes and decisions. Resolving an issue on Version 1 does not automatically prove that Version 2 contains the intended correction.

Use comments to explain the expected change. Use the decision controls to record the state of the selected version. Keeping these separate avoids turning a casual note into an accidental approval.

Use the explicit review sequence

  1. Work in Draft while you identify the file and add the initial notes.
  2. Mark the selected version ready for review when it is ready.
  3. Request changes when the file needs another pass.
  4. Resolve every blocking comment before recording approval.
  5. Record delivery only after approval. Reopen review explicitly if another blocking change appears.

This is an editable project record. It is not a signed certificate and does not establish that a named customer personally approved a file. If your business requires a formal signature, keep that separate evidence with your delivery.

Export something the next person can use

The standalone HTML report contains the recorded file identities, comment anchors, decision history and selected version comparison. The open editing list is a CSV of unresolved changes. It is more useful than copying a whole conversation into a spreadsheet and losing the connection to a version.

Keep the project JSON as your editable master. Send the original media through a suitable method you control when the recipient needs to inspect it. The report does not silently include those large files.

Optional private collaboration

Sign in to save a shared review and invite viewers or editors. Everyone invited can read all its notes. Recipients need the matching original files to view the media.

A workspace label is a short cloud-list label; the complete project title stays inside the document. A save includes the revision you opened. If another editor saved first, preserve your local JSON and deliberately reload or make a separate copy instead of overwriting their changes.
