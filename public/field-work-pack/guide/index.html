Choose a starting definition and make it yours

Start with one of eight editable checklists, from equipment handover to exhibition setup. Each starts empty, ready for your job.

Choose the one closest to the job and edit its fields. Write a specific instruction instead of “check everything.” A useful equipment-handover field might ask for the item count, a confirmation that the named accessories are present and a photo of the packed contents.

Field typeUse it forWhat completion means
ConfirmationAn explicit yes/done check against a written instruction.The required confirmation is selected.
MeasurementA quantity with an optional unit and inclusive limits.The entered number parses and is within the configured range.
PhotoVisible evidence that the reviewer needs to inspect.The local project contains the attached photo.

Required is a deliberate choice. Make a field required when the work should not proceed to review without it. An optional field can be left empty, but an invalid number entered into it still needs correction.

Create an order from the checklist revision you intend to use

A work order gets its own snapshot of the selected checklist. Later edits to the library do not silently change a job already in progress. This matters when the person doing the work and the person maintaining the template act at different times.

Give the order a useful title. Customer/site and reviewer labels are optional text you enter; you do not need to collect an email address or an attendee list to use the tool. Start work explicitly when you are ready to record the answers.

Record real answers instead of turning missing data into success

Use a dot for decimal values. A real zero is a number, while an empty required answer is missing. If the valid range is 10 through 20, both 10 and 20 are accepted; 9.9 and 20.1 need attention.

Select a JPEG, PNG or WebP photo. The project keeps an image copy so the report can include it. A required photo needs the image itself, not just its filename.

Example handover:

You need a count of six cases, a required “accessory list checked” confirmation and a packing photo. A count of six alone is insufficient. The outstanding-items list should still show the missing confirmation and photo until both are supplied.

Review and completion are separate actions

  1. Plan: the order exists but has not started.
  2. In progress: record your answers and inspect the live unresolved-items list.
  3. Ready for review: request review only after the required checks pass.
  4. Complete: explicitly record the review completion; the evidence check runs again.

Reviewed or completed controls stay locked until the order is reopened for changes. Reopening preserves the answers and requires review again. A reviewer label is an ordinary local record, not an authenticated professional signature.

Export the filled result

The HTML report contains the order's checklist snapshot, entered values, attached images, remaining requirements and local history. It can be opened independently. A report with missing requirements or without completed review is labelled Draft so a recipient can distinguish unfinished work.

Printing uses that report and waits for its images. Keep the full project JSON as an editable backup; exporting only the selected order is useful when you need to hand over one job without the rest of your local workspace.

Know which copy contains the photos

Browser-local storage retains the working project when a write succeeds. A failed storage write is reported; an open tab is not a backup. Download JSON when the work matters and keep the original images where you can find them.

Optional private cloud workspaces store metadata, not photo pixels. When you open one elsewhere, reattach the matching original images or transfer the full local JSON. A required photo that has not been reconnected cannot be used to present that cloud copy as a completed review.

Offline work and another device

Use the offline preparation control before relying on reopening without a connection. Check its saved status and keep a project JSON backup.

Sign in to invite viewers or editors. Everyone invited can read the shared project details. If someone saves first, keep your JSON and reload before combining the changes.
